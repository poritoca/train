駅間ナビ 59

iPhoneの通知・振動

ホーム画面に追加して通知を許可すると、画面を開いて見守っている間の接近を、iPhoneの通知でお知らせします。

ショートカットの作成や、ストア公開は不要です。通知の音・振動は端末の設定に従います。

調査：2026年9月22日。公式資料・公開仕様に基づく整理です。iPhone実機での通知・振動の確認は未実施です。

ホーム画面の通知を使う

  1. Safariで駅間ナビの公開URLを開き、共有 →「ホーム画面に追加」を選びます。「Webアプリとして開く」があればオンにします。
  2. 追加したアイコンから起動し、「その他 → 通知・振動 → 通知を許可する」を押します。
  3. iPhoneの「設定 → 通知 → 駅間ナビ」で通知・バナー・サウンドをオンにします。
  4. 「設定 → サウンドと触覚 → 触覚」を「常に再生」または「消音モードのときに再生」にします。音を出したくない場合は本体を消音モードにします。
  5. 集中モードや時刻指定要約で通知が抑制されない設定にして、実際にテストします。

電車に乗らずにテスト

「今すぐ通知」、または10秒・30秒・60秒後の通知を選べます。GPSや乗車経路の設定は不要です。カウントダウン中は画面を開いたままにしてください。「テストを中止」で取消できます。画面オフ・別アプリへの切り替え・ページを閉じる操作でも中止し、復帰後に古いテストは実行しません。

「通知の表示を要求しました」は、表示処理を受け付けたことを示します。実際にバナーが出たか、振動したかは端末で確認してください。iPhoneの振動パターンや長さを、このページから指定することはできません。

ホーム画面に追加しても、画面オフ中のGPS監視はできません。今回追加したのは、画面表示中に判断した接近をシステム通知で知らせる機能です。外部サーバーから配信するWeb Pushや、画面オフでも動く予約通知は実装していません。

Apple：通知の設定 ／ Apple：サウンドと触覚

画面を開いて使う：Brrrowserを試す

Brrrowserは、Webページ向けの振動機能を追加したiPhone用ブラウザです。開発元がnavigator.vibrate()への対応を明記しています。[12] 日本のApp Storeでは無料、iOS 16.6以降対応と案内されています。[13]

  1. Safari側で保存済みプリセットを使っている場合は、「保存した経路 → ファイルに書き出し」でJSONを保存します。別のブラウザには自動では引き継がれません。
  2. 駅間ナビの「その他 → 通知の設定・ほかの方法 → 別のブラウザ・ショートカットを使う場合」で、このページのURLをコピーします。公開済みのHTTPSのURLを使用してください。
  3. Brrrowserをインストールして、コピーした駅間ナビのURLを開きます。必要ならプリセットJSONを「保存した経路 → 読み込み」で取り込みます。
  4. 「その他 → 通知の設定・ほかの方法 → 別のブラウザ・ショートカットを使う場合」から「バイブを試す」を押します。バイブAPIが見つかるブラウザではテストボタンが表示されます。
  5. 「10秒後に試す」も押し、画面を開いたまま触れずに待ちます。ボタンに触れた瞬間だけでなく、少し時間がたっても振動するか確認できます。この案内や画面を閉じるとテストは中止します。
  6. 屋外などで位置情報を許可し、GPSの現在駅が取得できることを確認してから見守りを試してください。
App StoreでBrrrowserを確認

開発元の案内に基づく候補です。このアプリとのGPSの組み合わせ、実際の振動、画面保持はiPhone実機で未確認です。位置情報が取得できない場合は駅間ナビの見守りに使えません。画面ロック中のGPS動作も確認できていないため、Brrrowserでも画面を開いて利用する前提です。

駅間ナビはブラウザ名ではなく、実行中のバイブAPIを検出します。APIが提供されていれば既存の距離・1駅前・時間によるお知らせから呼び出します。音は追加していません。

画面を閉じて使う：ショートカット

普段使う降車駅・乗換駅ごとに「到着」のオートメーションを作ります。ブラウザを開き続ける必要がある駅間ナビのGPSとは別に、iPhone側の位置に基づいて実行します。[1]

  1. 駅間ナビの「その他 → 通知の設定・ほかの方法 → 別のブラウザ・ショートカットを使う場合」、またはプリセットの「通知の設定」を開き、駅名をコピーします。見守り中は「その他の操作 → iPhoneの通知・振動」からも開けます。
  2. 「ショートカット」アプリで、オートメーション → ＋ → 到着を選びます。項目名はiOSのバージョンによって異なります。
  3. 「場所」で駅を検索し、同名駅と間違っていないか路線・地図を確認します。地図の円で検知範囲を調整できます。早めに知りたい場合は範囲を広げるか、1つ前の停車駅を使います。停車する列車かどうかも確認してください。
  4. 必要なら時間範囲を指定します。往路は朝、復路は夕方などに分けると、通過するたびに振動するのを減らせます。
  5. 「すぐに実行」を選びます。「実行の前に尋ねる」がある場合はオフにします。「到着」は確認なしで実行できる作動条件です。[2]
  6. 「新規の空のオートメーション」などから、「デバイスを振動させる」を追加します。「繰り返す」を3回にしてその内側に置くと、振動を3回にできます。[3]
  7. 表示も必要なら「通知を表示」を追加し、「〇〇駅の近くです」などと入力します。[4] 音を出したくない場合は、アクションの詳細で「サウンドを再生」をオフにしてください。端末側の通知・触覚・集中モードの設定も確認します。
  8. 設定を保存し、まず目が覚めている状態で実際の移動中に試します。ロック中にも振動・通知するか、ご自身の端末で確認してください。
ショートカットを開く

上のボタンはiPhone用です。アプリを開くだけで、オートメーションは自動作成されません。未インストールならAppleの「ショートカット」を使用してください。

経路を変更したとき・使い終わったとき

駅間ナビとショートカットは別管理です。プリセットの変更・削除や「今回の設定を全解除」は、ショートカット側には反映されません。不要になったオートメーションは「ショートカット」で無効化・削除してください。[2]

到着オートメーションは、設定した範囲への進入が条件です。すでに範囲内にいる場合や、地下などで位置が取れない場合は期待どおりに作動しないことがあります。通知に遅れもあるため、正確な「駅到着」の判定には使わず、車内案内と合わせて利用してください。

「Chromeならバイブが使える」という説明は、Android版と混同しやすい点です。iPhone版は同じ条件ではありません。MDNの対応データではSafari/iOS WebViewのnavigator.vibrate()は非対応です。[5] Chrome・Edge・Firefoxの通常のiPhone版がWebKitを使うことから、同様の制約になると判断しています。[6] ChromeのWeb通知についてはGoogleも非対応と案内しています。[7]

配布地域・ブラウザの実装変更や、独自APIを追加した特殊なブラウザは別です。駅間ナビはブラウザ名だけで決めず、実行中のブラウザにバイブAPIがあるかを調べて表示します。APIがあっても実際の振動は端末設定に左右されるので、テストで確認してください。

スイッチを使って振動させる方法について

SafariのHTMLスイッチを利用した触覚フィードバックの実装例があります。[8] ただし、標準バイブAPIへの対応を意味するものではありません。駅に近づいた際の自動実行や、画面ロック中の動作を裏付ける確認が取れないため、今回の自動通知には組み込んでいません。

ほかの方法との比較

ホーム画面への追加とWeb Push

ホーム画面のWebアプリなら、通知の許可を得てWeb Pushを受け取れます。Apple Developer Programへの加入は不要です。[9]

ただし、Web Pushは外部から届く通知の仕組みです。ホーム画面への追加だけでは、ロック中のGPS監視はできません。位置情報APIは表示状態の制約を受けます。[10] 配信用サーバーを追加しても、駅への接近を検知する別の仕組みが必要です。駅間ナビ47は画面表示中のシステム通知に対応しています。外部サーバーによるWeb Push配信は追加していません。

ストアに公開せず、自作のiPhoneアプリを使う

MacのXcodeと無料のApple Accountを使い、自分のiPhoneへ入れてテストする方法はあります。ただし無料のPersonal Teamではプロビジョニングが7日で期限切れになり、再ビルド・再インストールが必要です。[11]

位置監視と通知をネイティブ側に実装すれば設計の自由度は上がりますが、Macの準備、初期設定、定期的な入れ直しが増えます。手軽な個人利用を優先する現状では、先に対応ブラウザの試用や標準ショートカットを検討するのがよいと判断しました。
