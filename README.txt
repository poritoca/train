v51 / 全区間タイムライン・GPS区間自動判定・全区間通知
========================================================
更新元: 202609231457_ekikan_gps_50_01.zip
私が直前に作成したv50を直接展開し、その内容から更新しています。旧版への巻き戻りはありません。

今回の変更
- 「全区間」表示を、現在の1乗車区間だけではなく、A区間→乗換→B区間→乗換→C区間…という旅程全体の縦タイムラインへ拡張しました。
- 各区間の路線名、全通過駅・停車駅・乗換駅・最終目的地を縦に並べ、駅数が多い場合も文字を極端に縮小せず縦スクロールで確認できます。
- 現在の乗車区間は明るく表示し、通過済み区間と今後の区間は段階的に抑えて、長い旅程でも現在位置を見失いにくくしました。
- GPSの実測点を、保存した全区間の線形に照合し、現在どの区間にいるかを自動判定します。乗換駅付近の誤切替を避けるため、精度・候補差・連続測位を使ったヒステリシスを入れています。
- 次区間へ十分な確度で移動したと判断した場合、その区間を自動で見守り対象へ切り替えます。各区間の降車駅ごとに、従来の近接・1駅前・到着などの通知判定を順番に再セットします。
- GPSで区間を確定できない場合は勝手に切り替えず、従来どおり乗換画面の「乗り換えた・次を開始」から手動で進められます。
- 通常画面と節電画面のどちらでも同じ全区間タイムラインを使います。「現在地へ」で現在区間付近へ戻れます。
- v50のGPS最終取得警告、節電画面ETA、ゆっくりした呼吸発光、10区切りの現在区間表示は維持しています。

駅間ナビ v47
============

前回配布の 202609220817_ekikan_gps_46_37.zip と全ファイル一致を確認し、その内容から更新しました。
駅データ・号車案内の解析・乗換サジェスト・往路/復路プリセット・10区切り表示は維持しています。

通知・振動
----------
1. GitHub PagesにZIP内の全ファイルを配置します。
2. iPhoneのSafariで開き、共有 → ホーム画面に追加。「Webアプリとして開く」があればオンにします。
3. 追加したアイコンから起動し、その他 → 通知・振動 → 通知を許可する。
4. iPhoneの設定 → 通知 → 駅間ナビで、通知・バナー・サウンドをオン。
5. 設定 → サウンドと触覚 → 触覚を「常に再生」または「消音モードのときに再生」。音を出さない場合は本体を消音モードにします。
6. 通知テストでバナー・通知センターと実際の振動を確認します。集中モード・時刻指定要約にも注意してください。

テストは「今すぐ通知」と10秒・30秒・60秒後に対応。電車・GPS・経路設定は不要です。
時間差テストはカウントダウンと取消ボタン付き。画面オフ・別アプリへの切り替え・ページを閉じた場合は中止します。
通知設定のダイアログで始めたテストは、そのダイアログを閉じても中止します。
テストは予約プッシュではありません。画面を閉じても動くタイマーではありません。
通知の許可はユーザーがボタンを押したときだけ要求します。拒否した場合は設定手順を案内します。
通知をオフにしても画面内の降車アラームは継続します。経路を終了・解除すると残っている降車通知を片づけます。

見守り中は、従来の近接・1駅前・到着・通過可能性・設定した確認時間などの判断をシステム通知にも反映します。
位置推定に基づくお知らせは、その旨を文面に表示します。同じ判断で通知を繰り返し作りません。
デモモードはシステム通知を発行しません。テスト通知は見守りとは独立しています。
通知タップで駅間ナビへ戻ります。開いている画面があればその画面に戻り、勝手に新しい見守りを始めません。

音・振動の注意
--------------
通知は端末の設定に従います。音を出さずに使いたい場合は、先に本体を消音モードにしてください。
通知の表示要求の成功は、実際のバナー・振動の保証ではありません。実機テストをお願いします。
iPhoneでは振動パターンや長さをWeb側から指定できません。
画面表示中のService Worker通知を使用し、外部配信サーバー・アカウント作成は不要です。
ホーム画面追加でも、ロック中のGPS監視はできません。外部Web Pushやロック中の予約通知は今回追加していません。
ほかの方法の案内は「通知の設定・ほかの方法」に折り畳んで残しています。

デザイン
--------
黒を基調にした静かな虹色の泡模様と、半透明のすりガラスを組み合わせました。
背景はCSSだけで描画し、画像取得や常時アニメーションを使いません。
透明度を下げるOS設定では不透明表示になり、ぼかし非対応環境でも文字を読みやすく保ちます。

駅名検索で経路を設定する
----------------------
1. ホームの「往路」または「復路」を選び、「経路を設定する」（保存済み経路がある場合は「新しい経路」）を押します。
2. 「乗る駅」「降りる駅」に駅名を入力します。候補に駅名と路線が一緒に表示されます。
3. 候補を押すと駅と路線を反映します。現在の路線の候補を優先します。
4. 「乗換を追加」で次の区間を設定します。最大8区間です。
5. 「この端末に保存」で、乗換を含む経路全体をプリセットとして保存します。
6. 保存せずその日だけ使う場合は「今回だけ開始」を押します。

検索は新規設定・保存済みプリセットの編集・見守り中の「今回の経路を変更」のすべてで使えます。
完全一致駅があればその駅を優先し、日本語の変換途中には候補を更新しません。
候補の路線へ変更した際、もう一方の駅がその路線にない場合は空欄に戻して選び直せます。
駅名を編集しただけでは見守り先は変わりません。変更画面の「今回の経路に適用」を押した時点で反映します。

往路／復路のプリセット
----------------------
- ホームと「保存した経路」の管理画面に往路／復路のタブがあります。
- 編集画面上部の「往路に保存／復路に保存」で保存先を選べます。既存のプリセットも移動できます。
- 管理画面の「復路を作成」は、区間順・乗車駅・降車駅・方面を逆にした下書きを作ります。保存するまでは元の経路を変更しません。
- プリセットは往路・復路合わせて最大30件です。
- v44で保存した分類のないプリセットは、内容を保ったまま往路に表示します。編集画面で復路へ変更できます。
- 見守り中の変更画面では「別のプリセットとして端末に保存」も使えます。元の保存内容や実行中の経路を勝手に上書きしません。

端末内への保存とファイルへの書き出し
----------------------------------
「この端末に保存」は、このブラウザのlocalStorageへ保存します。
同じ端末・ブラウザで開き直すと残りますが、ブラウザのデータを消した場合や別のブラウザでは引き継がれません。
「保存した経路」下部の「ファイルに書き出し」から、往路・復路を含むJSONファイルを保存できます。「読み込み」で復元できます。
従来の分類なしJSONも読み込めます。端末内に保存できなかった場合は失敗を表示し、入力内容を画面に残します。

全解除と削除
------------
- 見守り主画面の「今回の設定を全解除」: 継続測位・降車通知を止め、今回の全区間と再開候補を解除します。保存済みプリセットは残します。
- 初回設定／プリセット編集の「入力した設定を全解除」: 入力中の区間を空欄の1区間へ戻します。保存済みの元のプリセットは残します。
- 見守り中の変更画面の「今回の設定を全解除」: 見守りも終了し、新しい空欄の設定画面に戻します。
- 管理画面の「削除」、編集画面の「このプリセットを削除」: 選んだ保存データだけを削除します。すでに見守り中の経路はそのまま動作します。

次の停車駅までの10区切り表示
----------------------------
v44では従来の表示が詳細欄内にあり、見守り中に隠れていました。
v45から見守り主画面の「次の停車駅」の下に、駅名・10分割のバー・現在位置の印・割合を表示します。
前の停車駅から次の停車駅までを10分割し、選択した停車パターンに従って計算します。通過する駅でバーを区切り直しません。
逆方向・環状線の折返し位置にも対応します。GPSが古い場合は「推定位置」、手動補正時は「手動の現在駅」と表示し、位置未取得時には割合を出しません。
乗換準備中・目的駅への到着確認後は、その区間の進捗バーを隠します。

引き継いだ機能
