私が直前に作成したv50の27ファイルを直接展開して更新し、旧版は使用していません。

今回の確認
- JavaScript構文: journey-ui.js / dim-screen.js / sw.js、およびindex.html内の全インラインscriptをnode --checkで確認。
- HTML: id重複なし。通常画面の「現在区間 / 全区間」切替、節電画面の同切替、GPS最終取得表示を確認。
- CSS: tinycss2でパーサーエラー0件。複数区間の状態（通過済み / 現在 / 将来）、乗換点、区間バッジ用スタイルを確認。
- Service Worker: 51.0へ更新。SHELL 26項目のローカル参照はすべて存在。
- 全区間表示: 複数のlegを1本の縦タイムラインへ統合し、同じ乗換駅は重複表示を避けながら次区間情報を付与。駅数に応じて縦方向へ伸びる実装を確認。
- 乗換待ち・最終到着中でも「全区間」表示自体は隠さず閲覧できるよう確認。
- GPS区間判定: 実装と同一関数を抽出し、実在する収録座標で3区間（東海道線 横浜→品川 / 山手線 品川→渋谷 / 銀座線 渋谷→新橋）を検証。
  * 川崎では区間1を判定。
  * 品川の共通乗換点では次区間へ即時切替せず、現区間を保持。
  * 五反田では区間2を強く判定。
  * 渋谷の共通乗換点では候補差不足として次区間への確定を保留。
  * 表参道では区間3を強く判定。
- 自動区間切替は同じGPS timestampを重複カウントせず、新しい測位のみを連続判定へ使用。
- 隣接区間は通常3測位、乗換待ちは2測位、2区間以上の飛び越しはveryStrong判定かつ5測位を要求し、誤切替を抑止。
- 自動切替は現在より先の区間だけを対象とし、過去区間へGPS揺れで戻らないようにしている。
- 区間切替時は既存startLeg()を再利用し、当該区間の降車駅をalarm.targetへ設定し直すため、近接・1駅前・到着・推定フォールバック通知を各区間で順番に利用する。
- GPSで次区間を確定できない場合は、従来の「乗り換えた・次を開始」を残し、手動で継続できる。
- v50のGPS鮮度警告、節電画面ETA、8秒周期の呼吸発光、Wake Lock、10区切り現在区間表示は維持。

回帰防止
- station_support.json / guide-source-index.json / source_inventory.tsv / 各駅対応一覧などの駅・降車位置データは変更していません。
- notifications.js / visual-effects.js / iphone-alerts.html / manifest.webmanifest も変更していません。
