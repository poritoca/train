GitHub Pages向けオンライン号車案内 修正メモ（v18）

今回確認した症状
- 錦糸町: 取得には成功するが、実質同じ方向でも「方面を自動判定できない」へ落ち、号車が方面別に整理されないことがある。
- 保土ケ谷: 「掲載ページの特定」失敗となることがある。
- 一部駅: 初回失敗後、再取得ではすぐ成功する。

v18の対策
1. 方面判定を路線別スコア方式へ刷新
   - 外回り/内回り、上り/下り、東西南北
   - 終点・主要方面駅
   - 路線内の駅順
   - 路線ごとの方面別名
   を組み合わせて判定します。
2. 中央・総武各停/総武快速のような同一ページ内の別系統を serviceContext で分離します。
3. 方面共通データは「両方向共通の案内」と表示し、不一致扱いしません。
4. 本当に判定できない場合のみ、方面ごとに独立した枠で表示します。
5. 保土ケ谷/保土ヶ谷、市ケ谷/市ヶ谷、茅ケ崎/茅ヶ崎等を同一駅として照合します。
6. 駅名リンクの前方一致を禁止し、上野/上野広小路、新宿/新宿三丁目等の誤解決を防ぎます。
7. 全駅ページ→駅別詳細リンク→既知の駅別詳細URLの順に探索経路を補強します。
8. Jina Reader / AllOrigins の二重経路と自動再試行を維持します。
9. 900ms後の全体再探索も追加しています。
10. 旧オンライン解析キャッシュは parser4 名前空間への更新で自動破棄します。
11. Service Workerは18.1です。

検証
- 個別方面判定 30/30 PASS
- 全登録路線方向マトリクス 406/406 PASS
- 既存号車解析回帰テスト PASS
- JavaScript / Service Worker構文 PASS

GitHub Pagesへの反映
ZIPを展開し、中身をリポジトリへ同名上書きしてください。
特に index.html と sw.js は必ず同時に更新してください。
画面上部が「SILENT JOURNEY · 18」なら新HTMLです。

古いキャッシュについて
v18はオンライン解析キャッシュ名を変更しているため、過去の誤判定キャッシュは自動的に無効化されます。
Service Workerも18.1へ更新しているため、index.htmlとsw.jsの両方を上書きしてください。

注意
掲載元または第三者取得サービス自体が停止・制限された場合、オンライン部分のみ失敗する可能性があります。
静的内蔵データは影響を受けません。
