GitHub Pages向けオンライン号車案内 修正メモ（v17）

症状:
新小岩・錦糸町などで、最初は
「自動取得に失敗しました」
となるが、「再取得」を押すとすぐ表示される。

主因1: 掲載元のページ割りと旧推定のズレ
旧版は路線内の駅番号から「1ページ5〜6駅程度」と仮定して候補ページを推定していた。
しかし掲載元は、路線外の直通区間を同じ記事に含めたり、ページごとの駅数が一定でなかったりする。
横須賀・総武快速線では、新小岩・錦糸町は「新小岩〜東京」の3ページ目に掲載されるが、旧方式では正しい3ページ目を候補から外す場合があった。

主因2: 初回の外部取得サービスがコールド状態
Jina Reader / AllOrigins は、同じURLの最初の取得だけ時間がかかり、その直後の再取得では速くなる場合がある。
旧版は最初のタイムアウト後すぐ失敗表示にしていたため、利用者が「再取得」を押すことで実質2回目の取得を行っていた。

v17対策:
- 掲載元1ページ目から実在するページリンクを取得。
- 「A駅〜B駅」という区間ラベルとアプリの駅順を照合し、目的駅を含むページを特定。
- 推定候補はリンク解析失敗時のフォールバックとしてのみ利用。
- 候補を3ページずつ並列確認。
- 初回失敗後は700ms待って自動的に第2波を実行。
- 第2波はタイムアウトを延長。
- 同一ページの取得をセッション内で共有し、重複通信を減らす。

GitHub Pages反映:
ZIP内の全ファイルを同名上書きしてください。
特に index.html と sw.js は両方必要です。
画面上部が「SILENT JOURNEY · 17」なら新HTMLです。

注意:
第三者の公開取得サービスや掲載元自体が停止・制限された場合、オンライン部分だけは失敗する可能性があります。静的内蔵データは影響を受けません。
